# Bedrock 1.26.60

The 1.26.60 protocol family covers **protocol 2225**: BDS **1.26.60.6**, **1.26.61.1**, **1.26.62.1**, and **1.26.63.1**. Because all four builds speak the same protocol, `createBot({ version })` accepts the family (`'1.26.60'`) or any of the builds, and the bot reports `bot.version === '1.26.60'` and `bot.protocolVersion === 2225`. The data was probed on BDS 1.26.63.1, and both the probe and the live smoke test ran against all four builds. The four builds showed no observable differences: they share the same effect, enchantment, and biome IDs, entity sizes, and `available_commands` tree. Every other page in these docs uses 1.26.51 as its reference.

## Data {#data}

`@bedboo/bedrock-data` ships `data/1.26.60/`, generated from:

- minecraft-data 3.119.0 `data/bedrock/1.26.60` (blocks, block states, collision shapes, items). Materials come from `data/bedrock/1.26.51` in the same commit, which is what minecraft-data's own `dataPaths` uses for 1.26.60.
- CloudburstMC/Data `0021592` ("More 26.60 data"). Starting in 26.60, its `blocks.json` describes collision as `geometry.collision` instead of `collisionShape`. The generator reads both forms (see below).
- gophertunnel `d483610` (protocol 2225, level sound event names) and pmmp/BedrockData `bdb44a4` (biome IDs, as in 1.26.51).
- A live probe of BDS 1.26.63.1 (`scripts/probe/1.26.60.json`).

Differences from 1.26.51:

| | 1.26.60 | 1.26.51 |
|---|---|---|
| blocks / block states | 1 480 / 23 960 (new: `icicle`, `ice_crystal`, `disc_press`; `redstone_wire`, `fire` and `chorus_plant` have more states) | 1 477 / 22 091 |
| items | 2 080 (new: the three blocks and `frostbite_spawn_egg`; some network ids moved) | 2 076 |
| entities | 138 (new: `ice_ball`, 0.25 × 0.25) | 137 |
| particles | 81 (new: `ice_ball_break`) | 80 |
| effect ids, enchantment ids, biomes, sounds, other entity sizes | identical | |

Collision of `bamboo`, `pointed_dripstone`, and `sulfur_spike`: BDS offsets these blocks by position. The 26.60 Cloudburst dump gives their model boxes before that offset (`space: 'model_base'`, `translation: 'native_result'`). The generator keeps minecraft-data's boxes, as in 1.26.51, and verifies that they equal the model boxes shifted by one horizontal offset. Any other discrepancy still fails the generation.

## Wire differences {#wire}

bedboo builds every packet in the 1.26.51 shape and handles the differences that matter per family through `bot.supportFeature`:

- **Hand** (feature `actionPacketsHaveHand`): `animate` and the `item_use_on_entity` and `item_release` transactions include a `hand` byte (`main_hand` | `off_hand`) not present in 1.26.51. Without it, bedrock-protocol cannot write a swing, attack, or release at all. bedboo sends `main_hand`, except for `swingArm('left')` and the release that ends `activateItem(true)`, which send `off_hand`. `item_use` already included the hand in every family.
- **Item stack request numbering** (feature `stackRequestHasCraftReserved`): 1.26.60 inserted the `craft_reserved` action (wire type 16, legacy type 18). This shifted `non_implemented` and `results_deprecated` from legacy IDs 18 / 19 (in 1.26.51) to 19 / 20. bedrock-protocol maps wire names, but bedboo writes the legacy byte itself. If a craft still sends 19 for `results_deprecated`, BDS 1.26.60.6 drops the connection without a disconnect packet.
- The following changes are read-only or unused by bedboo, so they require no updates:
  - `level_chunk.client_biome_update`
  - `add_entity` / `add_player` `passenger_of_block`, `set_passenger_of_block`
  - `start_game.editor_level_migration_version`
  - `dimension_data` cloud fields
  - `player_list` (`play_fab_id` moved from the skin to the record)
  - `clientbound_update_sound_data` (now a tagged union)
  - environment attribute payloads, `EaseType` (now a varint)
  - four reserved container slot types
  - new packets: stonecutter recipe selection, cursor item drag, matchmaking, audio content
- Time is still synchronised with `sync_world_clocks`.

## Server behaviour {#server}

- **Commands:** every `value_type` ID used in 1.26.51 keeps the same number in 1.26.60. The only new one, 86, is the plain-word `timeMarkerName` used by the new `/time … <timeMarkerName> <occurrence>` and `/time … <clockName>` overloads. `bot.tabComplete` uses the 1.26.51 table.
- **Transport:** `server.properties` ships with `transport=nethernet` (as in 1.26.51) and adds `server-udp-ports=19132`, the UDP port(s) for NetherNet client connections. When running multiple servers on one host, give each its own value, just as with `server-port`.
- **Probe note:** a summoned camel sometimes spawns sitting (0.945 high). The data records the standing box (1.7 × 2.375, the same as in 1.26.51).
- The join sequence, loading-screen gate, chunk requests, server-authoritative inventory, item tags (recipes use the same tags as in 1.26.51), digging, placing, crafting, walking, and chat all behave as in 1.26.51 ([BDS notes](../bds.md)).
