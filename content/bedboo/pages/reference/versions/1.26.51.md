# Bedrock 1.26.51

Notes for the 1.26.51 protocol family, the default version: **protocol 2193**, BDS **1.26.50.5**, **1.26.51.1**,
and **1.26.52.3**. Pass `version: '1.26.51'` or any of these builds to `createBot` (or omit it: `false` and an absent
`version` both resolve to 1.26.51); `bot.version` is then `'1.26.51'` and `bot.protocolVersion` is 2193. The rest of this reference
describes this family unless a page states otherwise (see [BDS notes](../bds.md) and
[Connection and versions](../differences/connection.md#versions)).

## Data {#data}

`@bedboo/bedrock-data` ships `data/1.26.51/`, generated by `scripts/generate.js --version 1.26.51` from the sources
pinned in `scripts/sources.js` `PINS['1.26.51']` and the live probe `scripts/probe/1.26.51.json` (BDS 1.26.51.1):
22 091 block states, 2 076 items, and 89 vanilla biomes. The package's `NOTICE.md` lists the sources.

## One data set for three builds {#builds}

All three BDS builds share the same protocol and game data. Each build was started natively, joined with
`version: '1.26.51'`, and had its static join data compared against BDS 1.26.51.1 (the build the data was generated from):

| Compared | 1.26.50.5 | 1.26.52.3 |
|---|---|---|
| `start_game`: block palette checksum, `block_network_ids_are_hashes`, the 98 `block_properties`, experiments, game rules | same | same |
| `item_registry`: 2 076 items, each with the same runtime id, `component_based`, and version | same | same |
| `creative_content`: 124 groups, 1 980 entries | same | same |
| `biome_definition_list`: 89 definitions | same | same |
| `crafting_data`: every recipe and its network id (excluding per-run recipe UUIDs) | same | same |
| `available_entity_identifiers`, `voxel_shapes`, `trim_data`, `camera_presets`, `unlocked_recipes`, … | same | same |
| `available_commands`: the 82 commands, their overloads, parameter type ids, and enum contents | same | same |
| probe: effect ids, enchantment ids, biome order, entity bounding boxes | same | same |

The only differences are server-side or cosmetic:

- `start_game.engine` reflects the build (`1.26.50`, `1.26.52`).
- `available_commands` lists the world-generation feature names for `/place feature` in a different order (though the names are the same);
  bedboo resolves enum values through each packet's own value table, so nothing depends on the order.
- BDS 1.26.50.5 sends different `jigsaw_structure_data` template pools (used for structure generation, unused by bedboo).

Consequently, `data/1.26.51/`, the feature table, and the command type ids serve all three builds, and no build-specific table
is needed. Running bedboo against each build (testing spawn, registry, `blockAt`, inventory, chat, physics walk, dig, place,
entity tracking, tab completion, and disconnect) also showed no differences.

## Tests {#tests}

`pnpm test` runs the unit tests against this family by default (set `BEDBOO_VERSION=1.26.51` or a specific build such as
`BEDBOO_VERSION=1.26.52.3` to select it explicitly). Its join capture is `test/fixtures/1.26.51/join_flat` (from BDS
1.26.51.1).
