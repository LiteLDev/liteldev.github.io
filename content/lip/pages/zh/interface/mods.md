# 模组

模组页面列出服务器中已安装的内容。读完本页，你就能看懂这个列表，从文件、文件夹或网址安装模组，更新和卸载模组，并清楚每种更新的具体作用。

要查找并安装 levimc.org 上的模组，请使用[市场](./get_mods.md)页面。如果你还不熟悉按键和界面各部分，请先阅读[界面导览](./tour.md)。

## 列表

![装了四个模组的服务器的模组页面。编号标出操作行、用户安装的模组和没有方框的行。](/screenshots/zh-Hans/mods-01-list.svg)

1. **操作行**针对整个工作区。
2. **你的模组**：你自己安装的模组，每个前面都有一个方框 `[ ]`。
3. 没有方框的灰色行是**依赖**：你的模组所需要的模组。

每一行显示一个模组及其版本。名称是模组仓库的地址，例如 `github.com/LiteLDev/LeviOptimize`。`#` 后面的部分是所安装的变体，例如 `#lua`。

| 分组 | 是什么 | 可以做什么 |
| --- | --- | --- |
| 你的模组 | 你主动安装的模组。 | 勾选、更新、卸载。 |
| 依赖 | 因其他模组需要而安装的模组。 | 更新。不能单独卸载：没有模组需要它时会自动移除。 |

游戏（`github.com/LiteLDev/bds`）、加载器（`github.com/LiteLDev/LeviLamina`）以及仅它们需要的包不在列表中：lip 将它们与服务器一起管理。要更改它们的版本，请在[服务器](./server.md)页面使用**更改版本…**。

列表表头“已安装（5）”统计的是所有行，包括你的模组及其依赖。

在第一个模组上按 `↑` 会移到操作行，在最后一个操作行上按 `↓` 会回到列表。按 `Tab` 也能从操作行移到列表。

::: info
安装、更新或卸载后，列表顺序不会改变。每组都按名称排序，高亮也会留在原来的模组上。
:::

### 详情区

页面下方的区域显示当前高亮行的详细信息：名称、版本以及一句简介。

如果模组不是从仓库的正式版本安装的，还会多出第三行**来源**，说明它的安装来源：

![一个从分支安装的模组处于高亮。详情区有一行“来源  branch:main”。](/screenshots/zh-Hans/mods-09-source-branch.svg)

| “来源”一行 | 模组的安装来源 |
| --- | --- |
| 没有这一行 | 仓库的正式版本。“市场”安装的就是这种。 |
| `branch:main`、`tag:…` 或 `rev:…` | 仓库的某个分支、标签或提交。 |
| 以 `https://` 开头的网址 | 网上的 `.zip` 文件。 |
| 路径，例如 `D:\downloads\SpawnTweaks` | 磁盘上的 `.zip` 文件或文件夹。 |

![一个从网上的 .zip 文件安装的模组。“来源”一行显示它的网址，中间被省略。](/screenshots/zh-Hans/mods-10-source-url.svg)

![一个从文件夹安装的模组。“来源”一行显示文件夹的路径。](/screenshots/zh-Hans/mods-12-source-local.svg)

来源决定了**更新**的具体行为，详见[更新会做什么](#更新会做什么)。

### 没有服务器或没有模组的文件夹

如果文件夹里没有服务器，列表为空，第一个操作行**安装服务器…**会带你前往[服务器](./server.md)页面进行安装。安装模组前必须先有服务器。

![空文件夹的模组页面。操作行是“安装服务器…”“从来源安装…”和“市场”，列表写着“还没有模组。”](/screenshots/zh-Hans/mods-05-no-server.svg)

1. **安装服务器…** 仅在文件夹里还没有服务器时出现。
2. 详情区用一句话说明当前高亮的行。

如果服务器还没有安装模组，列表同样为空，“全部更新”的位置会变成**市场**：

![没有模组的服务器的模组页面。“市场”处于高亮，列表写着“还没有模组。”](/screenshots/zh-Hans/mods-06-no-mods.svg)

## 模组的菜单

在某一行上按 `Enter` 打开它的菜单。

![你的一个模组的菜单：详情、更新、更新到指定版本…、卸载。](/screenshots/zh-Hans/mods-02-menu.svg)

| 操作 | 作用 |
| --- | --- |
| 详情 | 显示 levimc.org 上关于该模组的信息。 |
| 更新 | 将模组更新到与服务器兼容的最新版本。 |
| 更新到指定版本… | 将模组换成你指定的版本。 |
| 卸载 | 移除模组及其文件。 |

依赖没有“卸载”选项：

![一个依赖的菜单：详情、更新、更新到指定版本…。详情区写着“因其他模组需要而安装。”](/screenshots/zh-Hans/mods-31-dependency-menu.svg)

## 详情

**详情**显示的内容与“市场”页面相同：模组的简介、作者、下载量、星标、许可证及其依赖项。

![对话框里的模组详情，按钮是“README”“在浏览器中打开”和“关闭”。](/screenshots/zh-Hans/mods-03-details.svg)

**README** 打开作者编写的模组说明。**在浏览器中打开**则在浏览器中打开该模组在 levimc.org 上的页面。

详情来自 levimc.org 的模组目录。如果目录中没有该模组（例如从本地磁盘安装的模组），lip 会显示“模组目录中没有这个模组的信息。”。

无法读取目录时，lip 会显示“无法读取模组目录。”。请等网络恢复后再试。

## 从来源安装

**从来源安装…** 用于直接指定来源安装模组，而不是从“市场”页面挑选。别人发给你的 `.zip` 文件或文件夹，或者 levimc.org 上没有的模组，都可以通过它安装。

1. 按 `↑` 高亮操作行**从来源安装…**，然后按 `Enter`。lip 会询问你指定模组的方式。

   ![“从来源安装”选项列表，有两行：“浏览…”和“输入来源…”。](/screenshots/zh-Hans/mods-14-install-choice.svg)

2. 从以下两种方式中选择一种。

### 浏览…

要安装磁盘上的 `.zip` 文件或文件夹，请选择**浏览…**。lip 会打开[文件浏览器](./tour.md#文件夹和文件浏览器)，列出其中的文件夹和 `.zip` 文件。

![文件浏览器位于 D:\downloads。一个 .zip 文件处于高亮。](/screenshots/zh-Hans/mods-15-browse.svg)

1. 如果是 `.zip` 文件，将其高亮并按 `Enter`。
2. 如果包是一个文件夹，打开该文件夹，然后选择**选择此文件夹**。

接着 lip 会显示计划：

![安装本地 .zip 文件的计划：一行文字说明将安装哪个模组的哪个版本，以及来自哪个文件。](/screenshots/zh-Hans/mods-16-install-local-plan.svg)

选择**应用**开始安装。在文件浏览器中按 `Esc` 可返回上一步的选择。

### 输入来源…

要安装网上的模组，请选择**输入来源…**。文本框初始为空，里面的灰色文字是示例。

![“从来源安装”对话框，文本框是空的。灰色的“github.com/owner/repo@1.2.3”是示例。](/screenshots/zh-Hans/mods-17-type-source-empty.svg)

输入或粘贴以下任意一种内容：

| 输入的内容 | 安装内容 |
| --- | --- |
| `github.com/engsr6982/PLand` | 该仓库中与服务器兼容的最新版本。 |
| `github.com/engsr6982/PLand@0.19.0` | 指定的版本。 |
| `github.com/LiteLDev/LegacyScriptEngine#lua` | 模组的 `lua` 变体。 |
| `github.com/owner/repo@branch:main` | `main` 分支。`tag:` 和 `rev:` 可按同样方式指定标签和提交。 |
| `https://example.com/mod.zip` | 该网址上的 `.zip` 文件。 |
| `D:\downloads\mod.zip` | 磁盘上的文件或文件夹。路径含有空格时，请用英文双引号括起来。 |

要一次安装多个模组，请用空格将它们隔开。

![同一个对话框，文本框里已输入“github.com/engsr6982/PLand@0.19.0”。](/screenshots/zh-Hans/mods-18-type-source.svg)

按 `Enter`。lip 会显示计划，选择**应用**开始安装。

![安装的计划：“Dry run: would install github.com/engsr6982/PLand 0.19.0 (3 files)”。](/screenshots/zh-Hans/mods-19-install-plan.svg)

如果该模组还需要其他模组，计划中也会一并列出，lip 会同时安装它们。来源的各种写法详见[用命令管理包](../guides/managing_packages.md)。

## 更新

更新有三种方式，每种都会先显示[计划](./tour.md#先预览再应用)。

### 更新

模组菜单中的**更新**会将该模组更新到与服务器游戏和 LeviLamina 兼容的最新版本。

![更新的计划：“would uninstall LegacyScriptEngine#lua 0.13.1”和“would install LegacyScriptEngine#lua 0.13.2”。](/screenshots/zh-Hans/mods-26-update-plan.svg)

更新即移除旧版本并安装新版本。选择**应用**：

![更新的结果：旧版本已卸载，新版本已安装，然后是“✓ 完成。”](/screenshots/zh-Hans/mods-27-update-result.svg)

随后列表会显示新版本：

![更新之后的列表。这个模组的版本变成了 0.13.2。](/screenshots/zh-Hans/mods-28-updated.svg)

### 更新到指定版本…

**更新到指定版本…** 会将模组替换为你选择的版本。目标版本既可以比当前版本新，也可以比当前版本旧，因此想退回旧版本时也用它。

1. 打开模组的菜单，选择**更新到指定版本…**。

   ![模组的菜单，“更新到指定版本…”处于高亮。](/screenshots/zh-Hans/mods-22-update-to-menu.svg)

2. 输入 `@` 后面的部分：填一个版本号（如 `0.13.0`），或者填 `branch:`、`tag:`、`rev:` 加上名称。

   ![“更新到指定版本”对话框。标签以“@”结尾，文本框里是“0.13.0”。](/screenshots/zh-Hans/mods-24-update-to.svg)

   如果 lip 无法识别输入的内容，对话框不会关闭，而是提示所需的格式。

   ![文本框里是“tag:”。下方一行写着“请填写版本号、branch:<名称>、tag:<名称> 或 rev:<提交>。”](/screenshots/zh-Hans/mods-23-update-to-invalid.svg)

3. 按 `Enter`，查看计划，然后选择**应用**。

   ![计划：“would uninstall LegacyScriptEngine#lua 0.13.1”和“would install LegacyScriptEngine#lua 0.13.0”。](/screenshots/zh-Hans/mods-25-update-to-plan.svg)

从网上的 `.zip` 文件或本地磁盘安装的模组没有其他版本可选。这类模组的该选项呈灰色，菜单中也会说明原因：

![一个来自网址的模组的菜单。“更新到指定版本…”是灰色，有一行写着“只有来自仓库的模组才有版本可选。”](/screenshots/zh-Hans/mods-11-url-menu.svg)

### 全部更新

**全部更新**是第二个操作行。它会更新你的所有模组，效果等同于对每个模组逐一执行“更新”。除非新版本的模组需要更新的依赖，否则依赖、游戏和加载器都保持不变。

![操作行“全部更新”处于高亮。详情区写着“更新你安装的所有模组。”](/screenshots/zh-Hans/mods-20-update-all.svg)

计划中只列出有变动的部分。下图中，四个模组里有一个有新版本：

![“全部更新”的计划：四行以“Resolving”开头的文字，然后是 LegacyScriptEngine#lua 的一次卸载和一次安装。](/screenshots/zh-Hans/mods-21-update-all-plan.svg)

如果某个模组是从文件夹或文件安装的，而该文件夹或文件已不存在，模组会保持原样，计划中也会加以说明。

### 更新会做什么

“更新”和“全部更新”对模组的具体操作，取决于模组当初的安装来源。查看[“来源”一行](#详情区)即可确定属于哪种情况。

| 模组是从哪里安装的 | 更新 |
| --- | --- |
| 仓库的某个版本，比如通过“市场”安装 | 更新到适配服务器的最新版本，不会停留在当初选择的版本。 |
| 一个分支，比如 `branch:main` | 留在该分支上，获取其最新状态。 |
| 一个标签或提交 | 留在原处。提交永远不变；标签仅在作者移动它时才会改变。 |
| 网上的 `.zip` 文件 | 重新下载该文件，并安装其中的当前内容。 |
| 磁盘上的 `.zip` 文件或文件夹 | 重新读取，并安装其中的当前内容。 |

下图中，“更新”重新下载了某个模组的网络文件，并发现其中是更新的版本：

![更新一个来自网址的模组的计划：旧版本将被卸载，并从同一个网址安装 1.2.1 版本。](/screenshots/zh-Hans/mods-13-update-url-plan.svg)

而“更新到指定版本…”无论模组原先来自哪里，都会将其替换为你指定的内容。对分支上的模组指定版本号后，它就会脱离该分支。

想让模组停留在某个版本，不更新它即可。没有办法“锁定”某个模组来让“全部更新”跳过它。

### 没有更新的版本时

当模组已是最新版本时，没有任何更改可应用：计划会显示“不会有任何更改。”，且只有一个**关闭**按钮。无论按多少次“更新”都是如此，通过“市场”按选定版本安装的模组也一样。

![什么都不会改的更新计划：“不会有任何更改。”，带一个“关闭”按钮。](/screenshots/zh-Hans/mods-30-up-to-date.svg)

有两类计划不会显示这句话，而是提示仅更新 lip 的记录。这两种情况下服务器上的文件都不会改变，选择应用或取消均可。

第一种：用**更新到指定版本…**指定了模组当前所在的版本。lip 会记下你指定了该版本。

第二种：对某个依赖按“更新”。此后 lip 会将该依赖算作你的模组：它会移入“你的模组”，前面出现方框，也可以卸载了。

![计划：“would mark LegacyRemoteCall 0.13.0 as explicitly installed.”和“只会更新 lip 的安装记录。”](/screenshots/zh-Hans/plan-03-record-only.svg)

## 卸载

1. 高亮要卸载的模组，按 `Enter`。
2. 选择**卸载**。

   ![模组的菜单，“卸载”处于高亮。](/screenshots/zh-Hans/mods-34-uninstall-menu.svg)

3. 查看计划。其中会列出该模组，以及所有不再被其他模组需要的依赖。

   ![卸载的计划：这个模组和一个依赖将被卸载。](/screenshots/zh-Hans/plan-01-changes.svg)

4. 选择**应用**。

   ![结果：“Uninstalling LegacyMoney 0.16.1”，然后是“✓ 完成。”](/screenshots/zh-Hans/mods-35-uninstall-result.svg)

卸载会移除模组安装的文件。模组在服务器运行期间自行生成的文件（如配置和数据）可能会保留在 `mods` 下对应的文件夹中。

## 一次处理多个模组

要一次更新或卸载多个模组，请先勾选它们。

1. 高亮一个模组，按 `Space`，前方的方框会变成 `[x]`。对其余模组重复此操作。

   ![两个模组已勾选。列表的表头写着“已安装（5） · 已勾选 2 个”。](/screenshots/zh-Hans/mods-07-checked.svg)

   1. 按 `Space` 勾选或取消勾选高亮的模组。
   2. 表头会显示已勾选的数量。

2. 按 `Enter`。此时打开的菜单针对所有已勾选的模组。

   ![标题为“已勾选 2 个”的菜单：LeviOptimize 的详情、更新 2 个模组、卸载 2 个模组、取消全部勾选。](/screenshots/zh-Hans/mods-08-batch-menu.svg)

   1. **……的详情**仅针对当前高亮的那一行，该行不一定是已勾选的模组。
   2. **更新 … 个模组**和**卸载 … 个模组**会在同一个计划中处理所有已勾选的模组。
   3. **取消全部勾选**会清除所有勾选。

只有你的模组可以勾选，依赖没有方框。完成更新或卸载后，勾选状态会自动清除。

## 服务器运行期间

工作区的服务器运行期间，此页面只能查看，不能修改。

![服务器运行期间的模组页面。一行黄色文字写着“服务器运行中，停止后才能更改模组。”，操作行是灰色。](/screenshots/zh-Hans/mods-36-server-running-page.svg)

1. 页面顶部会有一行文字提示服务器正在运行。
2. **从来源安装…** 和**全部更新**呈灰色，在上面按 `Enter` 没有反应。
3. 详情区显示“请先停止服务器。”

在模组的菜单中，“更新”“更新到指定版本…”和“卸载”同样因这一原因呈灰色。“详情”则照常可用。

![服务器运行期间一个模组的菜单。“更新”是灰色，有一行写着“请先停止服务器。”](/screenshots/zh-Hans/mods-04-server-running.svg)

如果在菜单打开期间服务器启动或停止，菜单会立即随之更新。

请前往[服务器](./server.md)页面停止服务器，改好模组后再重新启动。模组是在服务器启动时加载的，因此任何改动本来也需要重启才能生效。
