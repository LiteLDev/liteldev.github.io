# lip run

运行工作区的服务器。

## 概要

```
lip run [--managed [--detach]] [--accept-rosetta-license] [-h | --help]
```

## 说明

`lip run` 以工作区为工作目录、不带参数地启动工作区根目录下的服务器。运行方式有两种：

| | `lip run` | `lip run --managed` |
| --- | --- | --- |
| 服务器运行在 | 这条命令之下：**前台**运行。 | [守护进程](daemon.md)中，作为**托管服务器**。 |
| 关闭终端时 | lip 停止服务器。 | 服务器继续运行。 |
| 命令结束于 | 服务器退出之后。 | 你断开连接时，或服务器退出之后。带 `--detach` 时立即结束。 |
| Ctrl+C | 停止服务器。 | 停止服务器。 |

无论用哪种方式启动，一个工作区最多只有一个服务器在运行。

### 服务器

服务器是工作区根目录下的一个文件，具体是哪个文件取决于 [`lip setup`](setup.md) 安装的游戏和加载器：

| 工作区有 | 服务器 | 运行方式 |
| --- | --- | --- |
| 加载器（LeviLamina） | `bedrock_server_mod.exe` | 在 Windows 上由 lip 直接运行；在 Linux 和 macOS 上通过 Wine 运行。 |
| 没有加载器，构建为 `windows` | `bedrock_server.exe` | 同上。 |
| 没有加载器，构建为 `linux` | `bedrock_server` | 由 lip 直接运行，仅限 x64 的 Linux。 |

对 Linux 版服务器，如果环境变量 `LD_LIBRARY_PATH` 未设置或为空，lip 会将它设为 `.`，以便服务器找到同目录下的库。

在 Windows 上，如果 Visual C++ 运行库仅为用户安装在[数据目录](../files.md#数据目录)中、而未为系统安装，lip 在运行 Windows 版服务器时会把该目录放到 `PATH` 最前面，以便服务器找到它。

通过 Wine 运行时，lip 只使用安装在[数据目录](../files.md#数据目录)中的 `wine`，绝不使用其他 Wine；传入的唯一参数是服务器文件的绝对路径，并设置以下环境变量：

| 变量 | 值 |
| --- | --- |
| `WINEPREFIX` | 未设置或为空时：工作区中 `.lip/wine` 的绝对路径。前缀不存在时由 Wine 创建。 |
| `WINEDEBUG` | 未设置时：`-all`，关闭 Wine 的调试输出。 |
| `WINEDLLOVERRIDES` | 未设置时：`mscoree,mshtml=;winemac.drv,winex11.drv=d`，关闭 Wine Mono、Wine Gecko 以及 Wine 用于 macOS 和 X11 的图形驱动，使任何程序都不等待窗口或窗口服务器，未登录桌面的用户（例如通过 SSH）也能运行。 |

参见 [Linux 和 macOS](../../guides/linux_macos.md)。

### 启动

不带 `--managed` 时，`lip run` 依次执行以下步骤：

1. 获取**服务器锁** `.lip/server.lock`。如果另一个进程已持有该锁，说明该工作区已有服务器在运行，命令失败并给出说明。
2. 获取**工作区锁**。如果另一个进程已持有该锁，说明另一条命令正在更改工作区，命令失败。
3. 如果此前有操作被中断，将其完成或撤销。无法完成或撤销时，命令失败。
4. 释放工作区锁。
5. 如果工作区没有安装游戏，命令失败（消息会提到 `lip setup`）；如果服务器是 `bedrock_server` 而 lip 并非运行在 x64 的 Linux 上，命令失败；如果服务器文件不存在，命令失败。
6. 对 Windows 版服务器，安装服务器所需但系统缺少的组件：Linux 和 macOS 上的 Wine，以及 Microsoft Visual C++ 运行库（在 Windows 上由 lip 为当前用户安装，无需管理员权限）。安装失败时，命令失败。
7. 运行服务器，并等待它退出。
8. 服务器触发[重启](#重启)时，回到第 2 步。
9. 释放服务器锁。

服务器运行期间不持有工作区锁，因此可以在另一个终端中对同一工作区执行 `lip install`、`lip uninstall` 和 `lip update`。这些更改会在服务器下次启动时生效。界面在服务器运行期间不会执行这些操作，而是要求你先停止服务器。

### 输入与输出

服务器直接写入 `lip` 的标准输出和标准错误，并读取 `lip` 从标准输入读到的内容，因此像平时一样输入服务器命令即可。`lip` 的标准输入结束时，服务器的输入不会随之结束。重启后的服务器只读取上一个服务器退出之后的输入。

### 停止

按 Ctrl+C、发送 `SIGINT`、`SIGTERM` 或 `SIGHUP` 信号，以及在 Windows 上触发任何控制台控制信号（例如关闭控制台窗口），都会**要求 lip 停止**。

第一次收到停止要求时，lip 会向服务器发送一行 `stop`，服务器随即保存世界并退出。如果在服务器启动前就收到停止要求，服务器会在启动后收到这一行。无论收到多少次停止要求，lip 都不会先于服务器退出。如果服务器卡死，请手动结束服务器进程。

### 重启

同时满足以下全部条件时，lip 会重启服务器：

- 服务器以非 0 退出码退出；
- lip 未收到停止要求；并且
- 服务器退出那一刻，工作区配置中的 [`restart`](../configuration.md#restart) 为 `on-failure`。

此时 lip 会输出一条消息，等待 5 秒，然后从第 2 步开始重新启动服务器。在等待期间要求 lip 停止，会取消本次重启。

服务器在 10 分钟内最多重启 5 次。达到上限后若再次退出，lip 会输出消息说明不再重启，然后退出。

### 托管服务器

**托管服务器**是由[守护进程](daemon.md)运行、不属于任何特定客户端的服务器。它按上述方式运行，沿用启动它的那个 `lip` 进程的工作目录和环境变量，但有以下区别：

- 无论启动它的客户端发生什么，它都会继续运行。
- 它的输入来自已连接的客户端和界面，输出也会发送给所有已连接的客户端和界面。
- 只有已连接的客户端或界面才能要求它停止。
- 它不会交互式提问：在缺少 Rosetta 2 的 Apple 芯片 Mac 上，只有启动它的 `lip run --managed` 带有 `--accept-rosetta-license` 时，它才会安装 Rosetta 2，否则直接失败。从界面启动服务器时，改由界面询问。详见 [Apple 芯片的 macOS](../../guides/linux_macos.md#apple-芯片的-macos)。

守护进程为每个工作区最多运行一个托管服务器。在界面的[服务器](../../interface/server.md)页启动的服务器也是托管服务器，你可以从终端连接到它。

带 `--managed` 时，`lip run` 依次执行以下步骤：

1. 如果当前命令不是通过守护进程、而是由 lip 自行执行，命令失败：只有守护进程能运行托管服务器。
2. 如果该工作区没有正在运行的托管服务器，则启动一个，并等待其服务器进程启动。若启动失败，命令以同样的方式失败。
3. 若带有 `--detach`，命令立即结束；否则客户端会**连接**到该托管服务器。

### 连接

连接到托管服务器期间：

- 你输入的内容会发送给服务器。标准输入结束不会断开连接。
- 服务器的输出以及 lip 关于该服务器的消息会显示在你的终端上。如果服务器此前已在运行，你可能会先看到它之前的部分输出。
- 按 Ctrl+C（`SIGINT`；Windows 上还包括 Ctrl+Break）会要求服务器停止。连接会保持到服务器退出为止。
- 关闭终端（`SIGHUP`）、发送 `SIGTERM`、触发 Windows 上的其他控制台控制信号，或结束 `lip` 进程，都会**断开连接**：命令结束，而服务器继续运行。

如果在连接期间托管服务器停止运行，命令随之结束。

若要让托管服务器在后台继续运行，直接关闭终端或终端标签页即可。若要重新连接，在该工作区中再次运行 `lip run --managed`。

## 选项

| 选项 | 说明 |
| --- | --- |
| `--managed` | 将服务器作为托管服务器运行，或连接到正在运行的托管服务器。 |
| `--detach` | 与 `--managed` 配合使用：启动后不连接。不带 `--managed` 时属于用法错误。 |
| `--accept-rosetta-license` | 接受 Rosetta 2 的许可协议：在缺少 Rosetta 2 的 Apple 芯片 Mac 上，lip 不经询问直接安装它。见 [Apple 芯片的 macOS](../../guides/linux_macos.md#apple-芯片的-macos)。 |
| `-h`、`--help` | 输出帮助并退出。 |

## 输出

`lip run` 自身不产生结果输出。标准输出和标准错误中的内容均来自服务器。lip 自身的消息（例如重启前的提示）会写入标准错误。

## 退出状态

不带 `--managed` 时：

| 情况 | 退出码 |
| --- | --- |
| 服务器已启动 | 最后运行的那个服务器的退出码；通过 Wine 运行时为 `wine` 的退出码。在 Linux 和 macOS 上，被信号 n 终止时为 128 + n，例如 `SIGKILL` 为 137。lip 不另外输出消息。 |
| 服务器未启动 | 非 0，并输出消息说明原因。 |

带 `--managed` 时：

| 情况 | 退出码 |
| --- | --- |
| 带 `--detach`，或已断开连接 | `0` |
| 连接期间服务器停止运行 | 托管服务器的 `lip run` 退出码，同上表。 |
| 托管服务器无法启动 | 非 0，并输出消息说明原因。 |

## 示例

在前台运行服务器，按 Ctrl+C 停止：

```shell
lip run
```

在后台启动服务器并立即返回：

```shell
lip run --managed --detach
```

随后连接到该服务器，查看输出并输入命令：

```shell
lip run --managed
```

配置服务器在崩溃时自动重启：

```shell
lip config set restart on-failure --workspace
lip run --managed --detach
```
