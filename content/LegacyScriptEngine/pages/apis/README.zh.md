# LSE 插件开发概述

## ⛳ 放在前面

`LegacyScriptEngine`（以下简称**LSE**/**脚本引擎**）是一个适用于 Minecraft 基岩版专用服务器 `Bedrock Dedicated Server`（以下简称**BDS**）及 Windows 版 Minecraft 客户端的插件框架，提供强大的跨语言脚本插件支持和稳定的开发 API。  

> 欢迎参与脚本引擎的插件开发！

从这里开始，你将逐步熟悉脚本插件开发的基本要素和流程。

在动手开发之前，你需要对脚本引擎建立起系统的认识。本篇文档将帮助你搭建整体的知识框架，熟悉这些基础内容是学习开发的重要一步。



## 💊 数据类型

类型系统是框架设计中的关键部分。  
这些数据类型名称会频繁出现在开发文档中，因此在查阅 API 文档之前，请务必先熟悉它们。

### 通用数据类型约定

虽然脚本语言通常是弱类型的，一般无需关注具体的数据类型，但由于脚本引擎支持多种脚本语言，为了统一对接 API，下表定义了通用数据类型及其与各脚本语言类型的映射关系。

| 引擎数据类型 | JavaScript 数据类型 | Lua 数据类型 | 数据类型说明           |
| ------------ | ------------------- | ------------ | ---------------------- |
| `Null`       | `null`/`undefined`  | `nil`        | 空，未定义，不存在等等 |
| `Integer`    | `Number`            | `number`     | 整数                   |
| `Float`      | `Number`            | `number`     | 浮点数（小数，实数）   |
| `String`     | `String`            | `string`     | 字符串                 |
| `Boolean`    | `Boolean`           | `boolean`    | 布尔型                 |
| `Function`   | `Function`          | `function`   | 函数（方法）           |
| `Array`      | `Array`             | `table`      | 数组（列表）           |
| `Object`     | `Object`            | `table`      | 对象（映射，字典，表） |
| `ByteBuffer` | `ArrayBuffer`       | `table`      | 字节数组               |

文档中的 `任意类型` 表示可以使用上述任意一种类型的值。

除了上述标准类型外，引擎还提供以下自定义对象类型：

- `IntPos` - 整数坐标对象（详见 基础游戏接口）
- `FloatPos` - 浮点数坐标对象（详见 基础游戏接口）
- `Player` - 玩家对象（详见 玩家）- 在脚本引擎内实际注册的类名：`LLSE_Player`
- `Entity` - 实体对象（详见 实体）- 在脚本引擎内实际注册的类名：`LLSE_Entity`
- `Block` - 方块对象（详见 方块）- 在脚本引擎内实际注册的类名：`LLSE_Block`
- `BlockEntity` - 方块实体对象（详见 方块实体）- 在脚本引擎内实际注册的类名：`LLSE_BlockEntity`
- `Item` - 物品栏物品对象（详见 物品）- 在脚本引擎内实际注册的类名：`LLSE_Item`
- `Device` - 玩家设备信息对象（详见 玩家）- 在脚本引擎内实际注册的类名：`LLSE_Device`
- `Container` - 容器对象（详见 容器）- 在脚本引擎内实际注册的类名：`LLSE_Container`
- `Objective` - 计分项对象（详见 计分板）- 在脚本引擎内实际注册的类名：`LLSE_Objective`
- `Packet` - 数据包对象（详见 数据包）- 在脚本引擎内实际注册的类名：`LLSE_Packet`
- `NBT` - NBT Tag 对象（详见 NBT）
- `SimpleForm` - 普通表单对象（详见 表单构建器）- 在脚本引擎内实际注册的类名：`LLSE_SimpleForm`
- `CustomForm` - 自定义表单对象（详见 表单构建器）- 在脚本引擎内实际注册的类名：`LLSE_CustomForm`
- `Conf` - 配置文件对象（详见 配置文件）
- `DB` - 数据库对象（详见 数据库）
- `File` - 文件对象（详见 文件读写）
- `WSClient` - WebSocket 客户端对象（详见 网络）
- `Enum` - 枚举类型，通常储存于某些类型中，提供限定范围的可选项



## 📌 API文档描述约定

为了保证文档格式统一、清晰易读，脚本引擎的帮助文档统一采用以下描述约定。

> 后续所有 API 文档均遵循以下规则：

1. 关于文档中对 **函数参数类型** 的描述：  
   函数参数按 **参数名 : 参数类型** 的格式描述。  
   例如：cmd : `String` 表示一个**字符串**类型的变量 cmd。  
   若参数类型为 `Array<...>`，则表示由 <> 内类型元素组成的数组或列表。  

2. 关于文档中对 **可选参数** 的描述：  
   参数描述中标有 `可选参数` 时，代表该参数可以省略。  
   省略该参数时，引擎将使用描述中给出的默认值。  
   在 API 接口参数中，可选参数用 [ ] 括起。  
   例如：`pl.tell(msg[,type])`，其中的 `type` 即为可选参数。

## 📜 插件开发小贴士

下面是一些插件开发建议，希望能对你有所帮助：

- **不要重复**造轮子  
  在条件允许的情况下，尽量使用现有的功能库，不必每个功能都从头编写，这有助于整个生态的整合与发展。
- 为**用户**思考  
  设计界面和配置时，多从用户的角度出发。UI 和命令等交互设计应尽量清晰直观，符合常规使用习惯。
- 多角度思考**创新**  
  鼓励大家借鉴其他平台的优秀插件，也欢迎做出自己的创新。

## 📡 调试插件

在服务器控制台中输入以下命令即可进入对应的调试模式（Node.js 引擎不支持调试模式）：

- `jsdebug`: JavaScript 调试模式
- `luadebug`: Lua 调试模式
- `pydebug`: Python 调试模式

在调试模式下，你输入的所有内容都会作为脚本实时解析并执行，就像浏览器开发者工具的控制台一样。如果执行出错，控制台会输出错误报告。

再次输入相同的命令（`jsdebug`/`luadebug`/`pydebug`）并按回车即可退出调试模式。
